Рівень 2. Поведінкові патерни та Антипатерни

На минулому занятті ми будували "скелет" додатка: створювали об'єкти та з'єднували їх. Сьогодні ми займемося "нервовою системою".

Поведінкові патерни (Behavioral Patterns) відповідають за взаємодію між об'єктами. Хто кому передає дані? Хто відповідає за виконання завдання? Як розв'язати жорстку залежність між компонентами?

А в другій частині лекції ми розберемо Антипатерни — "архітектурні гріхи", які роблять майже всі новачки (і багато досвідчених розробників).

Iterator (Ітератор)

Надає спосіб послідовно обходити елементи складної колекції, не розкриваючи її внутрішнього устрою.

The Pythonic Way: Generators

У Java або C++ для цього потрібно створювати клас, що реалізує інтерфейс Iterator з методами next() і hasNext(). У Python ітератори вбудовані в мову.

Якщо вам потрібно ліниво перебирати дані, не пишіть класи. Пишіть Генератори.

# The Python Way: Generator
def large_file_reader(file_path):
    with open(file_path, 'r') as f:
        for line in f:
            if "ERROR" in line:
                yield line  # Повертаємо значення і "заморожуємо" стан

# Використання
for error_line in large_file_reader("server.log"):
    print(error_line)

Це і є патерн Ітератор, реалізований на рівні синтаксису мови (yield).

Strategy (Стратегія)

Визначає сімейство алгоритмів, інкапсулює їх і робить їх взаємозамінними.

Проблема

У вас є інтернет-магазин. Розрахунок вартості доставки залежить від оператора служби. Антипатерн:

if service == 'fedex':
    cost = weight * 1.5
elif service == 'dhl':
    cost = weight * 2.0
# І так далі...
graph LR Context[Order] -- uses --> Strategy[Shipping Function] Strategy -.-> FedEx Strategy -.-> DHL

The Pythonic Way: Functions as First-Class Citizens

Нам не потрібні класи FedExStrategy і DHLStrategy. У Python функції — це об'єкти. Ми можемо передавати їх як аргументи.

def calc_fedex(weight): return weight * 1.5
def calc_dhl(weight): return weight * 2.0

class Order:
    def calculate_shipping(self, weight, strategy: callable):
        return strategy(weight)

# Використання
order.calculate_shipping(10, calc_fedex)

Command (Команда)

Перетворює запит (виклик методу) на об'єкт. Це дозволяє передавати запити як аргументи, ставити їх у чергу, логувати або скасовувати.

Зв'язок із вашим досвідом: Celery

Ви вже використовували цей патерн, коли працювали з Celery.

Коли ви пишете task.delay(arg1, arg2), Celery:

  1. Бере функцію та аргументи.
  2. Серіалізує їх в об'єкт (JSON/Pickle).
  3. Кладе в чергу (Broker).
  4. Воркер дістає "Команду" і виконує її.
sequenceDiagram participant Client participant Queue as Broker (Queue) participant Worker as Invoker Client->>Queue: task.delay(data) (Create Command) Queue->>Worker: deliver task Worker->>Worker: execute()

У Python патерн Command часто реалізується саме через черги завдань, а не через класи.

Template Method (Шаблонний метод)

Визначає скелет алгоритму в базовому класі, але дозволяє спадкоємцям перевизначати окремі кроки, не змінюючи структуру алгоритму.

Зв'язок із вашим досвідом: Django Class-Based Views

Це ідеальний приклад. У ListView є метод get(), який викликає всередині себе ланцюжок:

  1. setup()
  2. get_queryset() <-- Ви перевизначаєте це
  3. get_context_data() <-- І це
  4. render_to_response()

Вам не потрібно писати всю логіку обробки HTTP-запиту заново. Ви змінюєте тільки "вставні" частини шаблону.

classDiagram class GenericView { +dispatch() +get_queryset()* +get_context_data()* } class MyProductListView { +get_queryset() +get_context_data() } GenericView <|-- MyProductListView

Observer (Спостерігач)

Визначає залежність "один-до-багатьох". Коли один об'єкт змінює стан, усі його підписники отримують сповіщення.

graph LR Subject((Subject)) -- "Notify()" --> ObsA[Observer A] Subject -- "Notify()" --> ObsB[Observer B] Subject -- "Notify()" --> ObsC[Observer C]

Зв'язок із вашим досвідом: Django Signals

Коли ви зберігаєте модель User, система відправляє сигнал post_save. На цей сигнал можуть бути підписані різні, незалежні частини системи:

  • Сервіс надсилання Welcome Email.
  • Сервіс аналітики.
  • Система створення профілю.

Це дозволяє розв'язати код (зменшити зв'язність). Модель User нічого не знає про email-розсилку.

Chain of Responsibility (Ланцюжок обов'язків)

Дозволяє передавати запит по ланцюжку потенційних обробників. Кожен обробник вирішує: обробити запит самому, відхилити його або передати далі.

graph LR Request --> Auth[Authentication] Auth -- next --> Log[Logging] Log -- next --> RateLimit[Rate Limiter] RateLimit -- next --> View[API Endpoint]

Зв'язок із вашим досвідом

У FastAPI та Django це називається Middleware. Запит від користувача проходить через шари:

  1. SecurityMiddleware (безпечно?)
  2. SessionMiddleware (чи є сесія?)
  3. CorsMiddleware (звідки запит?)
  4. ... Ваш код ...

Якщо SecurityMiddleware вирішить, що запит небезпечний, він перерве ланцюжок, і ваш код навіть не дізнається про запит.

State (Стан)

Дозволяє об'єкту змінювати свою поведінку залежно від внутрішнього стану. Ззовні здається, що об'єкт змінив клас.

Проблема

# Антипатерн "Великий IF"
class Order:
    def pay(self):
        if self.status == 'new':
            ...
        elif self.status == 'paid':
            raise Error("Already paid")
        elif self.status == 'shipped':
             raise Error("Too late")

Рішення

Винести логіку кожного статуса в окремий клас.

stateDiagram-v2 [*] --> New New --> Paid : payment_success Paid --> Shipped : ship_order Shipped --> [*]

У Python для простих випадків часто використовують бібліотеку transitions (FSM — Finite State Machine), замість ручного написання класів станів.

Частина 2: Архітектурні Антипатерни

Патерни — це те, як робити треба. Антипатерни — це те, як робити не треба, але як чомусь усі роблять.

Знання антипатернів допоможе вам проводити якісне Code Review і не стріляти собі в ногу.

Magic Numbers & Strings (Магічні числа)

Антипатерн: Використання чисел або рядків прямо в коді без пояснення.

# Погано
if user.access_level == 7: # Що таке 7? Адмін? Модератор? Бог?
    ...
time.sleep(86400) # Скільки це часу?

Як виправити: Використовуйте константи або Enum.

from enum import IntEnum

class AccessLevel(IntEnum):
    ADMIN = 7

if user.access_level == AccessLevel.ADMIN:
    ...
SECONDS_IN_DAY = 60 * 60 * 24
time.sleep(SECONDS_IN_DAY)

God Class (Божественний об'єкт)

Антипатерн: Клас, який знає занадто багато і робить занадто багато.

Ознаки:

  • Файл utils.py або manager.py на 2000 рядків.
  • Назва класу SystemManager або AppCore.
  • Методи: connect_db(), send_email(), calculate_taxes(), render_html().

Чому це погано? Порушення принципу SRP (Single Responsibility Principle). Такий клас неможливо тестувати і страшно змінювати.

Рішення: Декомпозиція. Розбийте клас на EmailService, TaxCalculator, DBRepository.

Premature Optimization (Передчасна оптимізація)

"Передчасна оптимізація — корінь усього зла". Дональд Кнут

Антипатерн: Ви пишете складний, нечитабельний код, використовуючи бітові зсуви або кастомні структури даних, тому що "так буде швидше", хоча ви навіть не запускали профайлер.

Приклад: Переписувати шматок логіки на C (Cython) до того, як проєкт взагалі запущено.

Правильний підхід:

  1. Make it work. Нехай запрацює.
  2. Make it right. Зробіть код чистим і читабельним.
  3. Make it fast. Якщо профайлер показав проблему — оптимізуйте тільки вузьке місце.

Reinventing the Wheel (Винаходити велосипед)

Антипатерн: Писати свої рішення для завдань, які вже вирішені в стандартній бібліотеці або популярних пакетах.

Приклади:

  • Писати свою функцію парсингу CSV замість модуля csv або pandas.
  • Писати свою криптографію (Ніколи! Не робіть! Цього!).
  • Писати свій ORM.

Square Wheel (Квадратне колесо): Коли ваше кастомне рішення не тільки дублює стандартне, але ще й працює гірше/з більшою кількістю багів.

Порада: Перед написанням утиліти витратьте 5 хвилин на гугління: "python library for X".
