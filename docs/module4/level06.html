Рівень 6: Основи ORM та SQLAlchemy

Пряме написання SQL-запитів у коді може бути багатослівним, схильним до помилок і прив'язувати ваш застосунок до конкретної бази даних. Ми познайомимося з ORM (Object-Relational Mapping) та заглибимося в SQLAlchemy — найпотужніший інструмент, який дозволяє взаємодіяти з реляційними БД мовою Python-об'єктів.

Ви зрозумієте, як ORM значно спрощує роботу з даними. Ми налаштуємо асинхронне підключення SQLAlchemy з драйвером psycopg3 і безшовно інтегруємо його у FastAPI через систему залежностей. Ви навчитеся створювати моделі даних, виконувати основні CRUD-операції (створення, читання, оновлення, видалення) та ефективно працювати з реляційними зв'язками між таблицями, заклавши надійну основу для повноцінних веб-застосунків.

Що таке ORM і навіщо вона потрібна?

ORM (Object-Relational Mapping) — це щось на кшталт "перекладача", який дозволяє вашому Python-коду спілкуватися з реляційною базою даних мовою об'єктів, а не "чистим" SQL.

Замість того, щоб писати INSERT INTO users ..., ви створюєте екземпляр класу User і викликаєте метод .save() (або аналог). ORM бере на себе всю "брудну роботу" з генерації та виконання SQL-запитів.

Що це дає на практиці:

  • ви пишете на Python, а не перемикаєтесь на SQL.
  • дозволяє легше змінювати СУБД (наприклад, з SQLite на PostgreSQL), оскільки ваш основний код не змінюється.
  • ORM автоматично захищає від базових SQL-ін'єкцій.

Звісно, за цю зручність ми платимо невеликим зниженням продуктивності, але для більшості завдань виграш у швидкості розробки та підтримки це повністю компенсує.

Знайомство з SQLAlchemy

SQLAlchemy — це основна і найпотужніша ORM в екосистемі Python, не прив'язана до жодного конкретного фреймворку. Це робить її ідеальним вибором для FastAPI.

На відміну від Django ORM, де багато чого приховано "під капотом", SQLAlchemy є більш прозорою. Ви безпосередньо працюватимете з такими концепціями як Engine (керує з'єднаннями з БД) та Session (керує транзакціями й об'єктами).

Ми будемо використовувати сучасний синтаксис SQLAlchemy, який чудово працює з анотаціями типів та асинхронністю.

Приклад запиту:

from sqlalchemy import select

# Замість 'objects.filter(...)' використовується функція select()
statement = select(User).where(User.age > 30)
# Сесія виконує запит і повертає результат
users = session.scalars(statement).all()

Підхід є більш багатослівним, ніж у Django, але дає більше контролю.

Базове асинхронне налаштування (database.py):

from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker
from sqlalchemy.orm import DeclarativeBase

# URL для підключення до PostgreSQL з драйвером asyncpg
DATABASE_URL = "postgresql+asyncpg://user:password@localhost/db_name"

# Створюємо асинхронний engine
engine = create_async_engine(DATABASE_URL)

# Фабрика для створення асинхронних сесій
async_session_maker = async_sessionmaker(engine, expire_on_commit=False)

# Базовий клас для всіх наших моделей
class Base(DeclarativeBase):
    pass

Інтеграція з FastAPI

Щоб кожен API-запит отримував власну ізольовану сесію для роботи з БД, ми використовуємо систему залежностей (dependencies) FastAPI.

Створення залежності для сесії (у database.py):

# ... (код з попереднього слайда) ...

# Залежність, яку ми будемо "інжектити" (inject, вводити) в ендпоінти
async def get_async_session():
    async with async_session_maker() as session:
        yield session

Цей код гарантує, що сесія буде створена для запиту і коректно закрита після його завершення, навіть у разі помилок.

Використання в ендпоінті (main.py):

from fastapi import Depends
from sqlalchemy.ext.asyncio import AsyncSession
from . import database

@app.get("/users/")
async def get_users(session: AsyncSession = Depends(database.get_async_session)):
    # У 'session' тепер знаходиться готова до роботи асинхронна сесія
    # ... (тут буде ваш код для запиту до БД) ...

Створення моделей даних

Модель у SQLAlchemy — це Python-клас, що описує таблицю в БД. Ми використовуємо декларативний стиль з анотаціями типів.

Ключові елементи:

  • успадкування від нашого класу Base.
  • атрибут __tablename__, що вказує назву таблиці.
  • атрибути класу з анотаціями Mapped та функцією mapped_column для опису стовпців та їхніх обмежень.

Приклад (models.py):

from sqlalchemy.orm import Mapped, mapped_column
from .database import Base # Імпортуємо наш Base

class User(Base):
    __tablename__ = 'users' # Назва таблиці в БД

    # Описуємо стовпці
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(nullable=False)
    email: Mapped[str] = mapped_column(unique=True, index=True)
    is_active: Mapped[bool] = mapped_column(default=True)

Цей підхід дає нам переваги статичної типізації та є легким для читання.

Основні типи даних та обмеження

SQLAlchemy надає типи даних, які мапляться на відповідні типи в SQL.

Тип в SQLAlchemy Тип в Python (Mapped[..._]) Опис
String(size) str рядок з обмеженням
Text str довгий текст
Integer int ціле число
Boolean bool логічне значення
Date, DateTime date, datetime дата та/або час
JSON dict, list зберігання JSON-об'єктів

Обмеження (аргументи mapped_column):

  • primary_key=True: первинний ключ.
  • unique=True: унікальність значення.
  • nullable=False: поле не може бути порожнім (NOT NULL).
  • index=True: створити індекс для прискорення пошуку.
  • default=значення: значення за замовчуванням.

Приклад:

from sqlalchemy import String
from datetime import date

class Post(Base):
    __tablename__ = 'posts'
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(100), unique=True)
    published_date: Mapped[date] = mapped_column(default=date.today)

CRUD-операції через SQLAlchemy (асинхронно)

Ось як вони виглядають в асинхронному SQLAlchemy.

Create:

async def create_user(session: AsyncSession, name: str, email: str):
    new_user = User(name=name, email=email)
    session.add(new_user) # Додаємо об'єкт до сесії
    await session.commit() # Зберігаємо зміни в БД
    await session.refresh(new_user) # Оновлюємо об'єкт, щоб отримати ID з БД
    return new_user

Read:

async def get_user_by_email(session: AsyncSession, email: str):
    statement = select(User).where(User.email == email)
    result = await session.execute(statement)
    user = result.scalar_one_or_none() # Отримати один об'єкт або None
    return user

Update:

async def update_user_name(session: AsyncSession, user_id: int, new_name: str):
    user = await session.get(User, user_id) # .get() — швидкий пошук за Primary Key (PK)
    if user:
        user.name = new_name
        await session.commit()
    return user

Delete:

async def delete_user(session: AsyncSession, user_id: int):
    user = await session.get(User, user_id)
    if user:
        await session.delete(user)
        await session.commit()
    return user

Робота з реляційними моделями

Зв'язок "один-до-багатьох":
Використовується ForeignKey для створення зв'язку на рівні БД і relationship для зручної навігації між об'єктами в коді.

from sqlalchemy import ForeignKey
from sqlalchemy.orm import relationship, Mapped, mapped_column
from typing import List

class User(Base):
    __tablename__ = 'users'
    id: Mapped[int] = mapped_column(primary_key=True)
    # relationship створює атрибут .posts для доступу до списку постів
    posts: Mapped[List["Post"]] = relationship(back_populates="author")

class Post(Base):
    __tablename__ = 'posts'
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    author_id: Mapped[int] = mapped_column(ForeignKey("users.id"))
    # relationship створює атрибут .author для доступу до об'єкта автора
    author: Mapped["User"] = relationship(back_populates="posts")

Тепер ви можете легко звертатися: user.posts поверне список постів, а post.author поверне об'єкт User.

Зв'язок "багато-до-багатьох":
Реалізується через окрему асоціативну таблицю.

# ... визначення асоціативної таблиці post_tag_association ...
class Post(Base):
    # ...
    tags: Mapped[List["Tag"]] = relationship(secondary=post_tag_association, back_populates="posts")

class Tag(Base):
    # ...
    posts: Mapped[List["Post"]] = relationship(secondary=post_tag_association, back_populates="tags")

Порівняння SQLAlchemy та Django ORM

Обидві ORM виконують одне й те саме завдання, але різними способами.

Аспект SQLAlchemy Django ORM
Підхід більш "явний" і близький до SQL, дає більше контролю. більш "магічний" та абстрактний, дає швидкість розробки.
Застосування ідеальний для FastAPI/Flask та будь-яких Python-проєктів. глибоко інтегрований в екосистему Django.
Міграції потребують окремого інструменту (Alembic). вбудовані (makemigrations, migrate).
Запит select(User).where(User.name == "Alice") User.objects.filter(name="Alice")

Django ORM — це швидкий старт у рамках Django. SQLAlchemy — це більш гнучкий та універсальний інструмент, який є стандартом для роботи з БД у FastAPI.

Тестування CRUD-операцій з pytest

Для тестів використовується окрема база даних (зазвичай SQLite in-memory) та асинхронні фікстури.

Налаштування тестової сесії (tests/conftest.py):

import pytest_asyncio
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker
from app.models import Base # Імпортуємо наш Base з моделями

ASYNC_DB_URL = "sqlite+aiosqlite:///:memory:"

@pytest_asyncio.fixture
async def async_session():
    engine = create_async_engine(ASYNC_DB_URL)
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all) # Створюємо таблиці

    TestingSessionLocal = async_sessionmaker(engine, expire_on_commit=False)
    async with TestingSessionLocal() as session:
        yield session # Передаємо сесію в тест

    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.drop_all) # Видаляємо таблиці

Приклад асинхронного тесту:

import pytest
from sqlalchemy import select
from app.models import User

@pytest.mark.asyncio # Маркер для асинхронного тесту
async def test_create_user(async_session):
    # Створюємо користувача
    new_user = User(name="John", email="john@example.com")
    async_session.add(new_user)
    await async_session.commit()
    assert new_user.id is not None

    # Перевіряємо, що він є в базі
    stmt = select(User).where(User.email == "john@example.com")
    result = await async_session.execute(stmt)
    user_from_db = result.scalar_one()
    assert user_from_db.name == "John"
