Рівень 19: Інтеграція Python та Telegram: Telethon і FastAPI

Коли стандартні Telegram Bot API обмежують ваш функціонал, і потрібен доступ до можливостей звичайного користувацького акаунту (наприклад, для парсингу чатів або автоматизації від свого імені), на допомогу приходить Telethon — потужна асинхронна Python-бібліотека для прямої взаємодії з Telegram MTProto API.

Ви зрозумієте ключові відмінності Telethon від бібліотек для ботів і навчитеся отримувати необхідні api_id та api_hash. Ми створимо та запустимо Telethon-клієнт, освоїмо отримання повідомлень та списків учасників чатів, а також асинхронну відправку повідомлень та файлів. Особливу увагу приділимо реакції на події в реальному часі за допомогою обробників і, головне, безшовній інтеграції Telethon з FastAPI, де клієнт запускатиметься разом з аплікацією, дозволяючи вашим ендпоінтам керувати Telegram-акаунтом або навіть "супер-ботом".

Що таке Telethon і навіщо він потрібен?

Telethon — це асинхронна Python-бібліотека для прямої взаємодії з Telegram API. На відміну від бібліотек для створення ботів, Telethon дозволяє вашому застосунку діяти як звичайний акаунт користувача (або бот).

Навіщо це потрібно?

  • читання чатів, надсилання повідомлень від свого імені, керування каналами.
  • вивантаження історії повідомлень, списків учасників із публічних та приватних чатів/каналів, де ви є учасником.
  • відстеження повідомлень за ключовими словами в реальному часі.
  • розробка власних версій Telegram-клієнта.

Telethon дає вам повний доступ до всіх можливостей Telegram API, доступних для звичайних користувачів.

Порівняння бібліотек: Telethon vs python-telegram-bot

Бібліотека Основне призначення Асинхронність Працює як... Доступ до API
Telethon автоматизація користувача, парсинг так (asyncio) користувач / бот повний (MTProto)
python-telegram-bot створення ботів так (asyncio) лише бот обмежений (Bot API)
aiogram створення ботів так (asyncio) лише бот обмежений (Bot API)

Встановлення Telethon та налаштування проєкту

1. Отримання API ID та API Hash:
Це ключі для вашого застосунку, а не для бота.

  • перейдіть на my.telegram.org та увійдіть до свого акаунта.
  • оберіть "API development tools" та створіть новий застосунок.
  • ви отримаєте api_id та api_hash.

2. Встановлення бібліотеки:

pip install telethon python-dotenv
pip freeze > requirements.txt

3. Зберігання ключів (безпека):
Ніколи не зберігайте api_id та api_hash прямо в коді. Використовуйте змінні середовища.
Створіть файл .env у корені проєкту:

API_ID=12345678
API_HASH=a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4
SESSION_NAME=my_telegram_session

Додайте .env та *.session до вашого .gitignore!

Створення та запуск Telegram-клієнта

Клієнт Telethon — це об'єкт, який керує вашим підключенням до Telegram.

Приклад (client.py):

import asyncio
from telethon import TelegramClient
from decouple import config # Зручна бібліотека для роботи з .env

# Завантажуємо змінні з .env
API_ID = config('API_ID', cast=int)
API_HASH = config('API_HASH')
SESSION_NAME = config('SESSION_NAME')

# Створюємо клієнт
client = TelegramClient(SESSION_NAME, API_ID, API_HASH)

async def main():
    # Підключаємось до Telegram
    await client.start()
    print("Клієнта успішно запущено.")
    # Отримуємо інформацію про себе
    me = await client.get_me()
    print(f"Ви увійшли як: {me.first_name} {me.last_name}")
    # ... тут буде основна логіка ...
    # Відключаємось
    await client.disconnect()

if __name__ == "__main__":
    asyncio.run(main())

Перший запуск: Telethon попросить вас ввести номер телефону, пароль (якщо є) та код підтвердження з Telegram. Після цього він створить файл сесії (*.session), і повторна авторизація не знадобиться.

Отримання повідомлень та учасників чату

Після підключення ви можете отримувати інформацію з чатів, у яких ви є учасником.

Отримати інформацію про чат/канал:

# 'entity' може бути username, посиланням або ID
entity = await client.get_entity('durov') # @durov
print(f"Назва: {entity.title}, ID: {entity.id}")

Вивантажити останні 10 повідомлень із чату:

# client.iter_messages() повертає асинхронний генератор
async for message in client.iter_messages('durov', limit=10):
    sender = await message.get_sender() # Отримуємо відправника
    print(f"[{message.date.strftime('%Y-%m-%d %H:%M')}] {sender.username}: {message.text}")

Отримати учасників групи:

# Працює лише для чатів, де ви можете бачити учасників
async for user in client.iter_participants('some_group_username'):
    print(f"ID: {user.id}, Ім'я: {user.first_name}, Username: {user.username}")

Асинхронне надсилання повідомлень

Надсилання текстового повідомлення:

# Надсилаємо повідомлення до чату 'me' (Збережені повідомлення)
await client.send_message('me', 'Привіт, це повідомлення від Telethon!')

Надсилання файлу:

# Надсилаємо фото з підписом
await client.send_file('me', 'path/to/my_photo.jpg', caption='Це я на відпочинку!')

Відповідь на повідомлення:

# message — це об'єкт повідомлення, отриманий раніше
await message.reply('Це відповідь на ваше повідомлення!')

Усі ці операції є асинхронними та мають виконуватися з await.

Реакція на події в реальному часі

Telethon може працювати в режимі "слухача" та реагувати на події (наприклад, нові повідомлення) в реальному часі за допомогою обробників подій.

Обробка нових повідомлень:
Декоратор @client.on(events.NewMessage) перетворює функцію на обробник.

from telethon import events

# Цей обробник реагуватиме на всі нові вхідні повідомлення
@client.on(events.NewMessage(incoming=True))
async def new_message_handler(event):
    # event.text — текст повідомлення
    # event.sender_id — ID відправника
    print(f"Отримано нове повідомлення від {event.sender_id}: {event.text}")
    if 'питання' in event.text.lower():
        # Відповідаємо на повідомлення
        await event.reply('Якщо у вас є питання, зверніться до нашого менеджера @manager_username')

# Щоб обробники працювали, клієнта має потрібно запустити, і він має працювати постійно
# client.run_until_disconnected()

Інші події: events.ChatAction (хтось увійшов/вийшов із чату), events.MessageEdited та інші.

Інтеграція Telethon з FastAPI

Ви можете керувати клієнтом Telethon через ендпоінти FastAPI. Це дозволяє створювати вебінтерфейси для автоматизації або запускати дії за зовнішнім тригером.

Архітектура:

  • Клієнт Telethon ініціалізується та запускається під час старту FastAPI-застосунку (у lifespan).
  • Ендпоінти FastAPI викликають методи клієнта (send_message, get_entity тощо).

Приклад (main.py):

from fastapi import FastAPI
from contextlib import asynccontextmanager
from telethon import TelegramClient
# ... імпорт налаштувань (API_ID, API_HASH, SESSION_NAME) ...

# Створюємо клієнт, але не підключаємо його
client = TelegramClient(SESSION_NAME, API_ID, API_HASH)

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Підключаємось під час старту
    await client.start()
    print("Telethon-клієнт запущено...")
    yield
    # Відключаємось при зупинці
    await client.disconnect()
    print("Telethon-клієнт зупинено.")

app = FastAPI(lifespan=lifespan)

@app.post("/send-message/")
async def send_telegram_message(chat_id: str, message: str):
    # Використовуємо запущений клієнт для надсилання повідомлення
    await client.send_message(chat_id, message)
    return {"status": "Повідомлення надіслано"}

Важливо: обробники подій (@client.on) працюватимуть, доки увімкнено FastAPI-застосунок.

Приклад: моніторинг чату та надсилання сповіщень

Завдання: відстежувати ключові слова в певному чаті та пересилати ці повідомлення до іншого чату (наприклад, адміністратору).

from telethon import events
import asyncio

# ID або username чатів/каналів
SOURCE_CHAT = 'some_public_channel' # Звідки читаємо
DESTINATION_CHAT = 'me' # Куди надсилаємо (в "Збережені")

KEYWORDS = ['fastapi', 'python', 'вакансія']

# Створюємо обробник лише для нових повідомлень у SOURCE_CHAT
@client.on(events.NewMessage(chats=SOURCE_CHAT))
async def keyword_monitor(event):
    message_text = event.text.lower()
    # Перевіряємо, чи є в повідомленні ключові слова
    if any(keyword in message_text for keyword in KEYWORDS):
        print(f"Знайдено ключове слово в повідомленні {event.id}")
        # Пересилаємо повідомлення
        await client.forward_messages(DESTINATION_CHAT, event.message)

Запуск:
Цей код працюватиме, доки клієнт увімкнений (наприклад, через client.run_until_disconnected() або всередині FastAPI lifespan).

Керування ботами через Telethon

Telethon може працювати не лише як користувач, але і як бот. Це корисно, якщо вам потрібні можливості акаунта користувача (наприклад, читання історії чатів) для керування вашим ботом.

Підключення як бот:

# BOT_TOKEN — токен, отриманий від @BotFather
await client.start(bot_token=BOT_TOKEN)

Обробка команд (через pattern):

@client.on(events.NewMessage(pattern='/start'))
async def start_handler(event):
    await event.reply('Привіт! Я бот, керований через Telethon.')

Переваги:

  • ви можете використовувати один і той самий синтаксис Telethon для роботи і з акаунтом користувача, і з ботом.
  • можна створити "супербота", де акаунт користувача виконує дії, недоступні звичайному боту (наприклад, додає бота до груп).

Повна система сповіщень: FastAPI + Telethon

Архітектура:

  1. FastAPI надає HTTP API для зовнішнього світу (наприклад, для вашого вебзастосунку чи інших сервісів).
  2. Ендпоінти FastAPI приймають запити на надсилання сповіщень.
  3. Telethon, активований всередині FastAPI, отримує команду від ендпоінта та надсилає повідомлення до потрібного Telegram-чату.
  4. База даних (наприклад, PostgreSQL із SQLAlchemy) може зберігати список чатів для розсилки, шаблони повідомлень тощо.

Приклад API для розсилки:

@app.post("/broadcast/")
async def broadcast_message(message: str):
    # Припускаємо, що get_subscriber_chats_from_db() — функція,
    # яка отримує ID чатів підписників із вашої БД.
    chat_ids = await get_subscriber_chats_from_db()

    # Асинхронно надсилаємо повідомлення всім підписникам
    tasks = [client.send_message(chat_id, message) for chat_id in chat_ids]
    await asyncio.gather(*tasks) # asyncio.gather для паралельного надсилання

    return {"status": "Розсилку запущено", "subscribers_count": len(chat_ids)}
