Рівень 13: Celery: фонові завдання та планування

Виконання довгих або ресурсоємних операцій безпосередньо в основному потоці API неминуче призводить до блокувань та погіршення користувацького досвіду. Celery — це потужна розподілена черга задач для Python, яка дозволяє 'віддавати на сторону' такі операції для виконання у фоновому режимі, зберігаючи чутливість вашого API.

Ми розберемо архітектуру Celery, що складається з продюсера, брокера та воркерів, і налаштуємо його мінімальний запуск з Redis. Ви навчитеся інтегрувати Celery як з FastAPI, так і з Django, асинхронно ставити задачі в чергу та ефективно відстежувати їхній стан.

Окремо розглянемо незамінний інструмент моніторингу Flower та можливості планування задач за розкладом за допомогою Celery Beat, що дозволить вам створювати масштабовані та ефективні фонові процеси.

Що таке Celery і навіщо він потрібен?

Celery — це розподілена черга завдань для Python. Простіше кажучи, це інструмент, який дозволяє вашому основному застосунку (FastAPI/Django) "віддавати на сторону" довготривалі або ресурсоємні операції для виконання у фоновому режимі.

Коли це потрібно:

  • надсилання email-сповіщень: API має відповісти "ОК" за мілісекунди, а не чекати 5 секунд, поки поштовий сервер обробить запит.
  • обробка завантажених файлів: стиснення зображень, конвертація відео.
  • генерація звітів: створення складних PDF або Excel-файлів.
  • звернення до повільних зовнішніх API.

Використовуючи Celery, ваш API залишається швидким на реагування, а вся важка робота виконується окремо, у фонових процесах-воркерах.

Архітектура Celery

Система на Celery складається з трьох ключових частин, що взаємодіють через брокера повідомлень.

  1. Producer (Продюсер):

    • це ваш застосунок (FastAPI/Django).
    • його завдання — створити завдання та надіслати його посереднику.

  2. Message Broker (Брокер повідомлень):

    • це посередник, зазвичай Redis або RabbitMQ.
    • він приймає завдання від продюсера і зберігає їх у черзі.

  3. Worker (Воркер):

    • це окремий Python-процес, який ви запускаєте на сервері.
    • він постійно стежить за чергою, забирає з неї завдання та виконує їх.

(Опціонально) Result Backend — місце, куди воркери можуть зберігати результати завдань (часто той самий Redis).

Мінімальний приклад: перший запуск Celery

Крок 1: Встановлення

pip install celery "redis[hiredis]"

Крок 2: Створення файлу із завданнями (tasks.py)

from celery import Celery
import time

# 'tasks' - назва модуля, broker - URL до Redis
app = Celery('tasks', broker='redis://localhost:6379/0')

@app.task # Декоратор, що перетворює функцію на завдання Celery
def add(x, y):
    time.sleep(5) # Імітація довгої операції
    return x + y

Крок 3: Запуск воркера
У терміналі, в папці з tasks.py, виконайте:

# -A tasks: вказує на екземпляр Celery у файлі tasks.py
celery -A tasks worker --loglevel=info

Воркер підключиться до Redis і чекатиме на завдання.

Крок 4: Виклик завдання (з іншого терміналу)

>>> from tasks import add

# .delay() — це асинхронний виклик. Він не чекає 5 секунд, а одразу повертає об'єкт AsyncResult
>>> result_object = add.delay(4, 6)
>>> print(result_object.id) # Кожне завдання має свій ID
'a1b2c3d4-e5f6-...'

Інтеграція Celery з FastAPI

Файл celery_app.py:

from celery import Celery

# Налаштовуємо брокер для завдань і бекенд для результатів
celery_app = Celery(
    "worker",
    broker="redis://localhost:6379/0",
    backend="redis://localhost:6379/1" # Краще використовувати іншу БД Redis для результатів
)

@celery_app.task
def send_email_task(recipient: str, subject: str):
    import time
    time.sleep(10) # Імітація довгого надсилання
    print(f"Лист до {recipient} з темою '{subject}' надіслано.")
    return "Success"

Файл main.py:

from fastapi import FastAPI
from celery_app import send_email_task

app = FastAPI()

@app.post("/send-email/fast")
def send_email_fast_route(email: str):
    # .delay() ставить завдання до черги й не чекає на його виконання.
    # API відповість миттєво.
    send_email_task.delay(email, "Швидкий спосіб")
    return {"status": "Завдання з надсилання email поставлено в чергу"}

Примітка: для дуже простих фонових завдань у FastAPI є BackgroundTasks, але Celery є набагато потужнішим для продакшену, оскільки працює в окремих, масштабованих процесах.

Інтеграція Celery з Django

Інтеграція з Django вимагає більш формального налаштування, щоб Celery "знав" про налаштування проєкту.

Файл myproject/celery.py (поряд з settings.py):

import os
from celery import Celery

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')
app = Celery('myproject')
# Завантажуємо конфігурацію з settings.py (змінні з префіксом CELERY_)
app.config_from_object('django.conf:settings', namespace='CELERY')
# Автоматично знаходимо файли tasks.py у всіх застосунках
app.autodiscover_tasks()

Файл myproject/__init__.py:

# Гарантує, що застосунок Celery завантажиться при старті Django
from .celery import app as celery_app
__all__ = ('celery_app',)

Файл myproject/settings.py:

# Налаштування для Celery
CELERY_BROKER_URL = 'redis://localhost:6379/0'
CELERY_RESULT_BACKEND = 'redis://localhost:6379/1'
# ... інші налаштування серіалізації ...

Файл myapp/tasks.py:

from celery import shared_task

# @shared_task дозволяє створювати завдання без прямого імпорту екземпляра Celery
@shared_task
def add(x, y):
    return x + y

Відстеження завдань

Виклик .delay() повертає об'єкт AsyncResult, який дозволяє відстежувати стан завдання.

Атрибути AsyncResult:

  • result.id: ID завдання.
  • result.status: статус (PENDING, STARTED, SUCCESS, FAILURE).
  • result.ready(): True, якщо завдання завершено.
  • result.get(): блокуючий метод для отримання результату. Якщо завдання завершилося з помилкою, .get() згенерує цей виняток.
  • result.result: результат, якщо status == 'SUCCESS'.
  • result.traceback: traceback, якщо status == 'FAILURE'.

Ендпоінт для перевірки статусу:

from celery.result import AsyncResult
from celery_app import celery_app # Імпортуємо наш екземпляр Celery

@app.get("/tasks/{task_id}")
def get_task_status(task_id: str):
    task_result = AsyncResult(task_id, app=celery_app)
    return {
        "task_id": task_id,
        "status": task_result.status,
        "result": task_result.result if task_result.ready() else None
    }

Моніторинг та логування: Flower

Flower — це вебінтерфейс для моніторингу та управління Celery. Обов'язковий інструмент для будь-якого продакшен-проєкту.

Встановлення:

pip install flower

Запуск:

# Для FastAPI проєкту
celery -A celery_app flower --port=5555

# Для Django проєкту
celery -A myproject flower --port=5555

Можливості Flower (доступно за http://localhost:5555):

  • перегляд статусів завдань у реальному часі.
  • моніторинг навантаження на воркери.
  • перегляд деталей завдань (аргументи, результат, помилки).
  • управління завданнями (скасування, повторний запуск) та воркерами.

Flower підключається до брокера та збирає інформацію від воркерів, надаючи вам єдиний інтерфейс для моніторингу всієї системи.

Планування завдань: Celery Beat

Celery Beat — це планувальник. Це окремий процес, який запускає завдання за розкладом, як cron у Linux.

Як працює:

  • ви визначаєте розклад для своїх завдань.
  • процес beat у потрібний момент надсилає завдання до брокера.
  • вільний worker забирає та виконує завдання.

Способи встановлення розкладу:

  1. У коді (через beat_schedule):

    # У файлі celery_app.py
from celery.schedules import crontab
celery_app.conf.beat_schedule = {
    'send-report-every-morning': {
        'task': 'tasks.send_daily_report',
        'schedule': crontab(hour=8, minute=0), # Щодня о 8:00
    },
}

  2. У базі даних (з django-celery-beat):

    • дозволяє керувати розкладами через адмін-панель Django.

Запуск (потрібно 2 процеси + воркери):

# Запуск воркерів
celery -A myproject worker -l info
# Запуск планувальника
celery -A myproject beat -l info
