Рівень 18: Основи розробки Telegram-ботів

Telegram-боти надають потужний канал для взаємодії з користувачами, але їх розгортання та інтеграція вимагають продуманої архітектури. Ми освоїмо основи розробки Telegram-ботів та їх інтеграцію з FastAPI, приділяючи особливу увагу масштабованій моделі Webhooks.

Ви дізнаєтеся, як працює Telegram Bot API, і чим Webhooks відрізняються від Polling, що є критично важливим для продакшен-систем. Ми налаштуємо бібліотеку python-telegram-bot та створимо першого ехо-бота, а потім безшовно інтегруємо його з FastAPI, де ваш API виступатиме в ролі вебхука, приймаючи та обробляючи оновлення від Telegram.

Ви навчитеся створювати асинхронні обробники команд та повідомлень, інтегрувати в них запити до зовнішніх API та налаштовувати логування, а також вибудовувати взаємодію бота з власним API FastAPI та базою даних.

Як працює Telegram Bot API?

Взаємодія між користувачем, Telegram та вашим ботом відбувається через Telegram Bot API.

Є два способи отримання оновлень (повідомлень від користувача):

  1. Polling:

    • ваш бот періодично (раз на кілька секунд) надсилає запит до серверів Telegram із запитанням: "Чи є для мене нові повідомлення?".
    • плюси: простота запуску та налагодження, не вимагає зовнішньої IP-адреси.
    • мінуси: затримка у відповіді, зайве навантаження через постійні запити.
    • ідеально для: розробки та налагодження.

  2. Webhooks:

    • ви надаєте Telegram URL вашого сервера (ендпоінт).
    • коли користувач надсилає повідомлення боту, сервери Telegram самі миттєво надсилають POST-запит із даними повідомлення на ваш URL.
    • плюси: миттєва реакція, відсутність зайвих запитів, висока ефективність.
    • мінуси: вимагає публічно доступної IP-адреси та HTTPS.
    • ідеально для: продакшену.

Потік даних через Webhook

sequenceDiagram participant User as Користувач participant TG as Сервери Telegram participant Bot as Ваш сервер (FastAPI) User->>TG: Надсилає повідомлення боту TG->>Bot: POST-запит на Webhook URL із даними повідомлення activate Bot Bot->>Bot: Обробка повідомлення Bot-->>TG: Відповідь (опційно, 200 OK) deactivate Bot TG->>Bot: Запит до Bot API для відправлення відповіді activate Bot Bot-->>TG: Відповідь із повідомленням deactivate Bot TG-->>User: Доставити відповідь користувачу

У цій презентації ми сфокусуємося на інтеграції через Webhooks за допомогою FastAPI.

Перший бот: структура та базові команди (Polling)

Спершу створимо простого "ехо-бота", що працює через Polling, щоб зрозуміти основи.

Файл bot.py:

import asyncio
from telegram import Update
from telegram.ext import Application, CommandHandler, MessageHandler, filters, ContextTypes

# --- Функції-обробники (хендлери) ---
async def start_command(update: Update, context: ContextTypes.DEFAULT_TYPE):
    """Обробник команди /start."""
    await update.message.reply_text("Привіт! Я ваш новий бот. Надішліть мені повідомлення, і я його повторю.")

async def echo_handler(update: Update, context: ContextTypes.DEFAULT_TYPE):
    """Обробник, який повторює текстові повідомлення."""
    text = update.message.text
    await update.message.reply_text(f"Ви написали: {text}")

# --- Основна логіка ---
def main():
    # Вставте ваш токен сюди
    TOKEN = "ВАШ_API_ТОКЕН_БОТА"
    # Створюємо застосунок
    application = Application.builder().token(TOKEN).build()

    # Реєструємо обробники
    application.add_handler(CommandHandler("start", start_command))
    # Цей обробник реагує на будь-який текст, що не є командою
    application.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, echo_handler))

    # Запускаємо бота в режимі Polling
    print("Бот запущений...")
    application.run_polling()

if __name__ == '__main__':
    main()
  • CommandHandler: реагує на команди (починаються з /).
  • MessageHandler: реагує на повідомлення певного типу (текст, фото тощо).

Інтеграція з FastAPI через Webhooks

Тепер перенесемо логіку бота на FastAPI, щоб він працював через Webhooks.

Процес:

  1. FastAPI-застосунок має один ендпоінт (наприклад, /webhook), який приймає POST-запити від Telegram.
  2. Під час старту застосунку ми "повідомляємо" Telegram про цей URL за допомогою методу set_webhook.
  3. Коли надходить запит, ми перетворюємо його JSON-тіло на об'єкт Update і передаємо на обробку до нашого застосунку python-telegram-bot.

Приклад (main.py):

from fastapi import FastAPI, Request, Response
from telegram import Update
from telegram.ext import Application, CommandHandler, MessageHandler, filters, ContextTypes
import asyncio

# --- Налаштування ---
TOKEN = "ВАШ_API_ТОКЕН_БОТА"
WEBHOOK_URL = "https://your-public-domain.com/webhook" # URL має бути публічним (використовуйте ngrok для локальної розробки)

# --- Обробники (як у минулому прикладі) ---
async def start_command(update: Update, context: ContextTypes.DEFAULT_TYPE): ...
async def echo_handler(update: Update, context: ContextTypes.DEFAULT_TYPE): ...

# --- Логіка FastAPI ---
# Створюємо застосунок PTB, але не запускаємо run_polling
ptb_app = Application.builder().token(TOKEN).build()
ptb_app.add_handler(CommandHandler("start", start_command))
ptb_app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, echo_handler))

# Створюємо FastAPI застосунок
app = FastAPI()

@app.on_event("startup")
async def startup_event():
    # Встановлюємо вебхук при старті
    await ptb_app.bot.set_webhook(url=WEBHOOK_URL)

@app.post("/webhook")
async def telegram_webhook(request: Request):
    """Приймає оновлення від Telegram."""
    update_data = await request.json()
    update = Update.de_json(update_data, ptb_app.bot)
    await ptb_app.process_update(update)
    return Response(status_code=200) # Повертаємо 200 OK, щоб Telegram не надсилав запит повторно

@app.on_event("shutdown")
async def shutdown_event():
    # Видаляємо вебхук при зупинці
    await ptb_app.bot.delete_webhook()

Для локальної розробки використовуйте ngrok для отримання публічного URL.

Асинхронна обробка та зовнішні API

Усі обробники в python-telegram-bot (v20+) є асинхронними (async def). Це дозволяє легко інтегрувати в них асинхронні операції, наприклад, запити до зовнішніх API за допомогою httpx.

Приклад команди /weather:

1. Сервісна функція для запиту до API погоди:

# services/weather.py
import httpx
from typing import Optional

OPENWEATHER_API_KEY = "ВАШ_КЛЮЧ_OPENWEATHER"
BASE_URL = "https://api.openweathermap.org/data/2.5/weather"

async def get_weather(city: str) -> Optional[str]:
    params = {"q": city, "appid": OPENWEATHER_API_KEY, "units": "metric", "lang": "uk"}
    async with httpx.AsyncClient() as client:
        try:
            response = await client.get(BASE_URL, params=params)
            response.raise_for_status() # Перевірка на 4xx/5xx помилки
            data = response.json()
            temp = data["main"]["temp"]
            desc = data["weather"][0]["description"]
            return f"Погода в місті {city}: {temp}°C, {desc}."
        except httpx.HTTPStatusError:
            return f"Не вдалося знайти місто '{city}'. Спробуйте ще раз."
        except Exception:
            return "Сталася помилка під час запиту погоди."

2. Обробник команди в боті:

# bot_handlers.py
from services.weather import get_weather

async def weather_command(update: Update, context: ContextTypes.DEFAULT_TYPE):
    if not context.args:
        await update.message.reply_text("Будь ласка, вкажіть місто. Приклад: /weather Київ")
        return
    city = " ".join(context.args)
    weather_text = await get_weather(city) # Асинхронний виклик
    await update.message.reply_text(weather_text)

# У main.py: ptb_app.add_handler(CommandHandler("weather", weather_command))

Логування подій та помилок

Логування є критично важливим для налагодження та розуміння того, як користувачі взаємодіють з вашим ботом.

Налаштування логування:
Використовуйте стандартний модуль logging Python.

import logging

# Налаштовуємо базовий логер
logging.basicConfig(
    format="%(asctime)s - %(name)s - %(levelname)s - %(message)s",
    level=logging.INFO
)
# Вимикаємо занадто "гучні" логери від бібліотек
logging.getLogger("httpx").setLevel(logging.WARNING)

logger = logging.getLogger(__name__)

Приклад використання в обробнику:

async def start_command(update: Update, context: ContextTypes.DEFAULT_TYPE):
    user = update.effective_user
    # Логуємо важливу подію
    logger.info(
        "Користувач %s (ID: %s) запустив команду /start.", user.username, user.id
    )
    await update.message.reply_text(f"Привіт, {user.first_name}!")

У продакшені налаштуйте логування у файли або централізовану систему (Sentry, ELK).

Інтеграція бота з вашим FastAPI та БД

Часто боту потрібно зберігати або отримувати дані з тієї ж бази даних, що й ваш основний API.

Архітектура:

  • FastAPI надає CRUD API для роботи з даними (наприклад, /api/users/, /api/notes/).
  • Telegram-бот (що працює як частина того ж FastAPI-застосунку або як окремий сервіс) не звертається до БД безпосередньо. Натомість він робить HTTP-запити до власного API.

Чому так?

  • розподіл відповідальності: API відповідає за бізнес-логіку та роботу з БД, бот — за взаємодію з користувачем.
  • повторне використання коду: логіка (наприклад, створення користувача) пишеться один раз в API і використовується як з вебу, так і з бота.
  • безпека та масштабованість: API може мати власну автентифікацію та масштабуватися незалежно від бота.

Приклад: реєстрація користувача через команду /start

# bot_handlers.py
import httpx

async def start_command(update: Update, context: ContextTypes.DEFAULT_TYPE):
    user = update.effective_user
    api_url = "http://127.0.0.1:8000/api/users/" # URL вашого API
    user_data = {"telegram_id": user.id, "username": user.username, "first_name": user.first_name}

    async with httpx.AsyncClient() as client:
        try:
            response = await client.post(api_url, json=user_data)
            if response.status_code == 201: # Created
                await update.message.reply_text(f"Привіт, {user.first_name}! Вас успішно зареєстровано.")
            elif response.status_code == 400: # Bad Request (наприклад, користувач вже існує)
                await update.message.reply_text("Ви вже були зареєстровані раніше.")
            else:
                response.raise_for_status()
        except httpx.RequestError:
            await update.message.reply_text("Не вдалося зв'язатися з сервером. Спробуйте пізніше.")
