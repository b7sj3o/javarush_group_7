Рівень 7: Alembic та керування міграціями

Зміни у схемі бази даних — неминуча частина розробки, яка вимагає суворого контролю версій та автоматизації для безшовного розгортання в команді. Ми вивчимо Alembic — де-факто інструмент для керування міграціями у проєктах з SQLAlchemy, який діє як Git для вашої схеми БД.

Ви дізнаєтеся, як Alembic дозволяє автоматизувати створення та застосування змін, зберігати повну історію версій та безпечно відкочувати невдалі модифікації. Ми пройдемо всі кроки налаштування Alembic, навчимося генерувати міграції на основі змін у моделях та застосовувати їх.

Окрему увагу приділимо особливостям роботи з Alembic у команді та стратегіям вирішення конфліктів при паралельній розробці.

Що таке Alembic і навіщо він потрібен?

Alembic — це інструмент для керування міграціями бази даних, створений спеціально для SQLAlchemy. Якщо SQLAlchemy — це ORM, то Alembic — це система контролю версій для схеми вашої бази даних, як Git для коду.

Навіщо він потрібен?
Коли ви змінюєте моделі SQLAlchemy (додаєте поле, створюєте таблицю), схема бази даних має бути оновлена. Робити це вручну (через ALTER TABLE ...) — прямий шлях до помилок, особливо при командній роботі.

Alembic дозволяє:

  • автоматизувати зміни структури бази даних.
  • зберігати історію змін у вигляді Python-скриптів (міграцій).
  • відкочувати (downgrade) невдалі зміни.
  • синхронізувати стан бази даних у всіх розробників та на всіх середовищах (dev, staging, prod).

Як працює Alembic?

Alembic порівнює поточний стан ваших моделей SQLAlchemy зі станом, записаним в останній міграції, і генерує скрипт міграції.

Міграція — це Python-файл, що містить дві основні функції:

  • upgrade(): описує, як застосувати зміни до бази даних (наприклад, op.add_column(...)).
  • downgrade(): описує, як скасувати ці зміни (наприклад, op.drop_column(...)).

Приклад міграції:

"""Додано поле email до таблиці users

Revision ID: 1975ea83b712
Revises:
Create Date: 2024-03-29 10:00:00.000000

"""
from alembic import op
import sqlalchemy as sa

# revision identifiers, used by Alembic.
revision = '1975ea83b712'
down_revision = None
branch_labels = None
depends_on = None

def upgrade() -> None:
    op.add_column('users', sa.Column('email', sa.String(), nullable=False))

def downgrade() -> None:
    op.drop_column('users', 'email')

Ці файли зберігаються в репозиторії разом із кодом.

Встановлення та налаштування Alembic

Крок 1: Встановлення

pip install alembic
pip freeze > requirements.txt

Крок 2: Ініціалізація
У корені проєкту виконайте команду. Вона створить папку alembic із файлами конфігурації.

alembic init alembic

Крок 3: Налаштування alembic.ini
Вкажіть URL вашої бази даних. Alembic працює в синхронному режимі, тому тут потрібен синхронний URL, навіть якщо ваш застосунок асинхронний.

# alembic.ini
# ...
# sqlalchemy.url = driver://user:pass@host/db
sqlalchemy.url = postgresql+psycopg2://user:password@localhost/db_name
# або для SQLite:
# sqlalchemy.url = sqlite:///./test.db
Примітка

Для PostgreSQL вам може знадобитися встановити синхронний драйвер: pip install psycopg2-binary.

Крок 4: Налаштування alembic/env.py
"Навчіть" Alembic знаходити ваші моделі SQLAlchemy.

# alembic/env.py

# ... інші імпорти ...

# Додайте шлях до вашого проєкту, щоб Alembic міг знайти моделі
import sys
from os.path import abspath, dirname
sys.path.insert(0, dirname(dirname(abspath(__file__))))

# Імпортуйте Base з вашого файлу з моделями
from app.models import Base
# --- ВАШІ ЗМІНИ ЗАКІНЧУЮТЬСЯ ТУТ ---

# решта згенерованого коду...

# Вкажіть Base.metadata як ціль для автогенерації
# Знайдіть цей рядок у файлі і переконайтеся, що він вказує на вашу Base.metadata
target_metadata = Base.metadata

# ...

Створення та застосування міграцій

Основні команди:

  1. Автогенерація міграції:
    Alembic порівнює ваші моделі зі станом БД і генерує скрипт міграції.

    alembic revision --autogenerate -m "Add email column to User model"

  2. Застосування міграцій:
    Застосовує всі нові міграції до бази даних, оновлюючи її до останньої версії.

    alembic upgrade head

  3. Відкат міграції:
    Відкочує останню застосовану міграцію.

    alembic downgrade -1

Приклад: додавання поля в таблицю

Крок 1: Змініть модель у app/models.py
Додамо поле email до моделі User.

# app/models.py
class User(Base):
    __tablename__ = 'users'
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str]
    email: Mapped[str] = mapped_column(unique=True) # <-- Нове поле

Крок 2: Згенеруйте міграцію
Alembic виявить нове поле і створить для нього міграцію.

alembic revision --autogenerate -m "Add email to User model"
# Вивід: INFO  [alembic.autogenerate.compare] Detected added column 'users.email'
#        Generating alembic/versions/xxxx_add_email_to_user_model.py

Крок 3: Застосуйте міграцію
Ця команда виконає SQL-запит ALTER TABLE users ADD COLUMN email ....

alembic upgrade head
# Виведення: INFO  [alembic.runtime.migration] Running upgrade ... -> xxxx, Add email to User model

Тепер у вашій базі даних таблиця users має новий стовпець email.

Керування версіями та історія

Alembic зберігає інформацію про поточну версію схеми в спеціальній таблиці alembic_version у вашій БД. Ви можете керувати цими версіями.

Корисні команди:

  • Переглянути історію всіх міграцій:

    alembic history --verbose

  • Переглянути поточну версію БД:

    alembic current

  • Відкотити на одну версію назад:

    alembic downgrade -1

  • Відкотити до конкретної версії (ID можна взяти з alembic history):

    alembic downgrade <revision_id>

  • Застосувати до конкретної версії:

    alembic upgrade <revision_id>

Робота в команді: конфлікти та злиття

Усі файли міграцій мають зберігатися в Git!

Конфлікт міграцій ("diverged branches").
Виникає, коли два розробники в різних гілках створюють міграції, що базуються на тій самій попередній версії. В Alembic з'являються дві "голови".

Рішення: Merge-міграція.
Alembic може створити спеціальну міграцію для злиття цих двох гілок.

alembic merge heads -m "Merge user and post feature branches"

Робочий процес у команді:

  1. Перед створенням нової міграції завжди виконуйте git pull та alembic upgrade head, щоб оновити свою базу до актуального стану.
  2. Створіть свою міграцію (alembic revision --autogenerate ...).
  3. Закомітьте та відправте до репозиторію і зміни в моделях, і новий файл міграції.

Інтеграція з Django

Django має власну вбудовану систему міграцій, яка глибоко інтегрована з фреймворком. Для більшості Django-проєктів слід використовувати саме її.

Alembic може знадобитися, якщо:

  • У вас гібридний проєкт, де частина працює на Django, а частина — на FastAPI/Flask зі спільною базою даних SQLAlchemy.
  • Ви працюєте з базою даних, якою керує інший застосунок на SQLAlchemy.

Ніколи не керуйте однією й тією ж таблицею одночасно через міграції Django та Alembic! Це призведе до хаосу. Розподіліть відповідальність: одні таблиці належать Django, інші — SQLAlchemy/Alembic.
