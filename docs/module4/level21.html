Рівень 21: Безпека та CORS у FastAPI

У веб-розробці браузерні політики безпеки, такі як Same-Origin Policy, можуть блокувати легітимні запити до вашого API, а сам API потребує надійного захисту від несанкціонованого доступу. Ми сфокусуємося на безпеці вашого FastAPI API, починаючи з механізму CORS (Cross-Origin Resource Sharing).

Ви зрозумієте, що таке CORS, чому він критично важливий для крос-доменних запитів, і як працює його 'передпольотна' фаза (Preflight Request). Ми навчимося налаштовувати CORSMiddleware у FastAPI, гнучко вказуючи дозволені домени, методи та заголовки, а також ефективно діагностувати типові помилки CORS.

Буде чітко підкреслено роль автентифікації та авторизації (JWT) як другої лінії оборони API, і ми коротко розглянемо необхідність налаштування SSL/TLS (HTTPS) для продакшен-розгортань, забезпечуючи комплексний захист вашого застосунку.

Що таке CORS і навіщо він потрібен?

CORS (Cross-Origin Resource Sharing) — це механізм безпеки, вбудований у веббраузери. Він дозволяє серверу (вашому API) вказати, яким іншим джерелам (доменам, схемам, портам) дозволено робити до нього запити.

За замовчуванням браузери дотримуються Same-Origin Policy, яка забороняє JavaScript-коду, завантаженому з одного сайту, робити HTTP-запити до API на іншому сайті.

CORS — це спосіб послабити цю політику, але зробити це контрольовано та безпечно. Без налаштування CORS ваш фронтенд просто не зможе "достукатися" до вашого API.

Як працює CORS?

Коли фронтенд намагається зробити кросдоменний запит, браузер виступає в ролі "охоронця".

1. Простий запит (GET):

  • браузер надсилає запит до API.
  • він чекає від сервера відповіді із заголовком Access-Control-Allow-Origin: <домен_фронтенду> (або *).
  • якщо заголовок є і відповідає джерелу фронтенду, браузер передає відповідь до JavaScript. Якщо ні — блокує відповідь і видає помилку CORS у консолі.

2. Попередній запит (Preflight Request):

  • для "складних" запитів (наприклад, PUT, DELETE або з нестандартними заголовками на кшталт Authorization) браузер спочатку надсилає OPTIONS-запит на той самий URL.
  • у цьому запиті він "цікавиться" у сервера: "Чи можна мені зробити PUT-запит із заголовком Authorization з цього домену?".
  • сервер має відповісти на OPTIONS-запит переліком дозволених доменів, методів та заголовків.
  • якщо відповідь позитивна, браузер надсилає вже основний PUT-запит.

Як налаштувати CORS у FastAPI?

FastAPI надає спеціальний Middleware для простого та гнучкого налаштування CORS.

1. Встановлення не потрібне (є частиною FastAPI).
2. Імпорт: from fastapi.middleware.cors import CORSMiddleware.
3. Додавання Middleware до застосунку:

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

# Список доменів, яким дозволено робити запити до нашого API
origins = [
    "http://localhost:3000",      # Для локальної розробки React
    "http://localhost:8080",      # Для локальної розробки Vue/Angular
    "https://my-production-frontend.com", # Наш продакшен-фронтенд
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=origins, # <-- Вказуємо список дозволених джерел
    allow_credentials=True, # Дозволити cookies (важливо для автентифікації)
    allow_methods=["*"],    # Дозволити всі стандартні методи (GET, POST, etc.)
    allow_headers=["*"],    # Дозволити всі заголовки
)

CORSMiddleware має бути одним з перших у ланцюжку middleware.

Налаштування параметрів CORS

allow_origins: список дозволених доменів. Не використовуйте ["*"] у продакшені, якщо ваше API не є повністю публічним і не вимагає автентифікації. Це дозволить будь-якому сайту робити запити.

allow_methods: список дозволених HTTP-методів. Рекомендується вказувати явно, наприклад, ["GET", "POST", "PUT", "DELETE"], замість ["*"].

allow_headers: список дозволених HTTP-заголовків, які клієнт може надсилати. ["*"] дозволяє всі. Для API з токенами часто потрібно щонайменше Content-Type та Authorization.

allow_credentials=True:

  • дозволяє браузеру надсилати в крос-доменних запитах cookies та заголовки Authorization.
  • важливо: якщо allow_credentials=True, то allow_origins не може бути ["*"]. Ви повинні явно перелічити дозволені домени.

Типові помилки CORS та їх діагностика

Коли ви бачите помилку CORS у консолі браузера, це майже завжди проблема на боці бекенду, який не надіслав правильні заголовки.

Помилка: No 'Access-Control-Allow-Origin' header is present on the requested resource.

  • причина: домен вашого фронтенду не внесено до списку allow_origins на бекенді.
  • рішення: додайте URL вашого фронтенду до allow_origins.

Помилка: CORS preflight channel did not succeed. або Method PUT is not allowed by Access-Control-Allow-Methods in preflight response.

  • причина: ваш фронтенд намагається використати HTTP-метод (наприклад, PUT) або заголовок (наприклад, X-Custom-Header), який не дозволений у allow_methods або allow_headers на бекенді.
  • рішення: додайте потрібний метод/заголовок у відповідні списки в налаштуваннях CORSMiddleware.

Помилка: The value of the 'Access-Control-Allow-Origin' header in the response must not be the wildcard '*' when the request's credentials mode is 'include'.

  • причина: ви намагаєтеся надіслати запит з credentials (наприклад, cookie або Authorization токен) до API, де allow_origins=["*"] та allow_credentials=True.
  • рішення: замініть allow_origins=["*"] на явний список доменів.

Діагностика: використовуйте вкладку "Network" (Мережа) в інструментах розробника браузера, щоб подивитися на OPTIONS (preflight) та основний запити і перевірити заголовки відповіді від сервера.

Безпека API: Токени та Авторизація

CORS — це перша лінія оборони, яка відсікає запити з недозволених сайтів. Але це не захищає від того, що хтось із дозволеного сайту (або через Postman/curl) виконуватиме дії, на які він не має прав.

Для цього потрібна автентифікація та авторизація, яку ми вивчали на Рівні 4.

Процес:

  1. CORS перевіряє, чи можна запиту з цього домену взагалі "поспілкуватися" із сервером.
  2. Якщо так, FastAPI приймає запит.
  3. Authentication (наприклад, за JWT у заголовку Authorization) визначає, хто цей користувач.
  4. Authorization (Permissions) визначає, чи можна цьому користувачеві виконувати цю дію.

Приклад залежності для перевірки токена:

from fastapi import Depends, HTTPException, Header
from jose import jwt, JWTError
# ... (SECRET_KEY, ALGORITHM, ...)

async def verify_token(authorization: str = Header()):
    # Видаляємо "Bearer " з заголовка
    token = authorization.split(" ")[1]
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        # Тут можна додати перевірку, чи існує користувач з id з payload
        return payload
    except JWTError:
        raise HTTPException(status_code=401, detail="Невалідний токен")

Цю залежність потрібно додавати до захищених ендпоінтів.

Налаштування SSL/TLS (HTTPS) для API

HTTPS — це обов'язково для будь-якого продакшен API.

SSL/TLS шифрує весь трафік між клієнтом та сервером.
Без HTTPS ваші токени автентифікації, логіни, паролі та всі дані, що передаються, є вразливими до перехоплення.

Налаштування:

  • HTTPS налаштовується на рівні вебсервера (Nginx, Apache) або балансувальника навантаження, а не у FastAPI.
  • вам знадобиться SSL-сертифікат (можна отримати безкоштовно через Let's Encrypt за допомогою certbot).

Запуск Uvicorn з SSL (лише для локальної розробки/тестів):

  1. Згенеруйте самопідписаний сертифікат:

    openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem -days 365 -nodes

  2. Запустіть Uvicorn, вказавши шляхи до ключа та сертифіката:

    uvicorn main:app --ssl-keyfile=./key.pem --ssl-certfile=./cert.pem

У продакшені це завдання має виконувати Nginx.

Приклад повного захищеного API

Цей приклад поєднує CORS, JWT-автентифікацію та захищений ендпоінт.

from fastapi import FastAPI, Depends, HTTPException, Header
from fastapi.middleware.cors import CORSMiddleware
from jose import jwt, JWTError
from datetime import datetime, timedelta, timezone

app = FastAPI()
SECRET_KEY = "дуже_складний_секретний_ключ_з_.env"
ALGORITHM = "HS256"

# 1. Налаштування CORS
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://myfrontend.com", "http://localhost:3000"],
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["Authorization", "Content-Type"],
)

# 2. Логіка JWT (може бути в окремому файлі auth.py)
def create_access_token(data: dict):
    expire = datetime.now(timezone.utc) + timedelta(minutes=30)
    data.update({"exp": expire})
    return jwt.encode(data, SECRET_KEY, algorithm=ALGORITHM)

async def verify_token(authorization: str = Header()):
    token = authorization.split(" ")[1]
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        return payload
    except JWTError:
        raise HTTPException(status_code=401, detail="Невалідний токен")

# 3. Ендпоінти
@app.post("/login")
async def login():
    # Тут має бути перевірка username/password
    token = create_access_token({"sub": "user123", "role": "user"})
    return {"access_token": token}

@app.get("/secure-data")
async def get_secure_data(payload: dict = Depends(verify_token)):
    return {"message": "Це захищені дані!", "user": payload.get("sub")}
