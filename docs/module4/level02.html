Рівень 2: Створення асинхронного REST API з FastAPI

Традиційні синхронні підходи до створення API можуть призвести до блокувань та низької продуктивності при великій кількості запитів. Ми освоїмо фундаментальні концепції асинхронного програмування в Python за допомогою async та await — ядра FastAPI, що дозволяє будувати неблокуючі та високопродуктивні системи.

Ви навчитеся створювати асинхронні ендпоінти, які ефективно обробляють паралельні запити. Детально розберемо роботу з динамічними параметрами шляху та запиту, а також методи обробки даних від клієнта через POST, PUT та DELETE-запити.

Особливу увагу буде приділено стратегіям ефективної обробки помилок та винятків з використанням HTTPException, що дозволить вашому API завжди надавати інформативні та передбачувані відповіді.

Асинхронність у Python: async та await

Асинхронне програмування дозволяє вашому застосунку виконувати довгі операції, не блокуючи основний потік виконання. Поки одне завдання чекає на відповідь, застосунок може обробляти інші запити.

Ключові слова:

  • async def: оголошує функцію як корутину (coroutine) — спеціальну асинхронну функцію, виконання якої можна призупинити.
  • await: "каже" програмі призупинити виконання поточної корутини, доки асинхронна операція (яку ми "очікуємо") не завершиться. В цей час керування повертається до event loop, який може запустити інші завдання.

Простий приклад:

import asyncio

# Оголошуємо асинхронну функцію
async def fetch_data():
    print("Починаємо завантаження даних...")
    # Призупиняємо виконання на 2 секунди, імітуючи мережевий запит
    await asyncio.sleep(2)
    print("Завантаження даних завершено.")
    return {"data": "Деяка інформація"}

async def main():
    print("Виконуємо головну функцію.")
    result = await fetch_data() # Очікуємо на результат
    print(f"Результат: {result}")

# Запускаємо асинхронний код
asyncio.run(main())

Цикл подій та asyncio.gather

Event Loop — це ядро асинхронного застосунку. Його можна уявити як "диригента", який керує виконанням багатьох асинхронних завдань. Він запускає завдання, і якщо воно доходить до await, цикл подій призупиняє його та перемикається на інше, готове до виконання завдання.

asyncio.gather — це функція, яка дозволяє запускати декілька асинхронних завдань конкурентно (майже одночасно) і чекати на їх завершення.

import asyncio
import time

async def task(name: str, delay: int):
    print(f"Завдання '{name}': старт, чекаємо {delay} сек.")
    await asyncio.sleep(delay)
    print(f"Завдання '{name}': кінець")

async def main():
    start_time = time.time()
    # Запускаємо обидва завдання конкурентно
    await asyncio.gather(
        task("A", 2),
        task("B", 1)
    )
    print(f"Всі завдання завершено за {time.time() - start_time:.2f} сек.")
# Виведення:
# Завдання 'A': старт, чекаємо 2 сек.
# Завдання 'B': старт, чекаємо 1 сек.
# Завдання 'B': кінець
# Завдання 'A': кінець
# Всі завдання завершено за 2.00 сек. (не 1+2=3 сек!)

FastAPI використовує asyncio та event loop "під капотом" для ефективної обробки тисяч одночасних запитів.

Асинхронні ендпоінти у FastAPI

FastAPI початково спроєктований для роботи з асинхронними функціями. Ви можете оголосити ваші функції-обробники (ендпоінти) за допомогою async def.

Коли FastAPI отримує запит на такий ендпоінт, він запускає вашу корутину у своєму циклі подій. Якщо всередині вашої функції зустрічається await (наприклад, під час запиту до БД або зовнішнього API), FastAPI "відпускає" воркер для обробки інших вхідних запитів, а не чекає на завершення операції.

Приклад:

import asyncio
from fastapi import FastAPI

app = FastAPI()

# Цей ендпоінт не блокуватиме сервер на 5 секунд.
# Сервер зможе обробляти інші запити, поки цей "спить".
@app.get("/long-task")
async def long_task():
    await asyncio.sleep(5)
    return {"message": "Готово! Я почекав 5 секунд, не блокуючи інші запити."}

@app.get("/short-task")
async def short_task():
    return {"message": "Я виконався швидко!"}

Ця діаграма ілюструє ключову перевагу async def в ендпоінтах FastAPI. Замість того, щоб блокуватися на довгій операції, воркер негайно звільняється для обробки інших запитів.

Path Parameters

Path Parameters (параметри шляху) дозволяють створювати динамічні URL, де частина шляху є змінною. Вони визначаються в URL за допомогою фігурних дужок {} і передаються у функцію як іменовані аргументи.

FastAPI використовує анотації типів для автоматичної валідації та перетворення цих параметрів.

Приклад:

from fastapi import FastAPI

app = FastAPI()

# {item_id} - це Path Parameter
@app.get("/items/{item_id}")
async def read_item(item_id: int): # FastAPI перевірить, що item_id — це число
    return {"item_id": item_id}

@app.get("/users/{username}")
async def get_user(username: str): # Тут параметр буде рядком
    return {"username": username}

@app.get("/files/{file_path:path}")
async def read_file(file_path: str): # Тип :path дозволяє читати шляхи зі слешами
    # Запит /files/home/user/report.txt -> file_path = "home/user/report.txt"
    return {"file_path": file_path}

Якщо тип даних в URL не відповідає анотації (наприклад, /items/abc замість числа), FastAPI автоматично поверне клієнту помилку 422 Unprocessable Entity.

Query Parameters

Query Parameters (параметри запиту) — це пари ключ=значення в URL після ?, що використовуються для фільтрації, сортування та пагінації. Вони визначаються як аргументи функції, які не є параметрами шляху.

from fastapi import FastAPI, Query
from typing import Optional, List

app = FastAPI()

# URL: /products/?category=phones&max_price=500.00
@app.get("/products")
async def get_products(
    category: str, # Обов'язковий query-параметр
    max_price: Optional[float] = None, # Опціональний
    tags: List[str] = Query(None) # Список: ?tags=sale&tags=new
):
    response = {"category": category}
    if max_price:
        response.update({"max_price": max_price})
    if tags:
        response.update({"tags": tags})

    # ... тут логіка фільтрації товарів за параметрами ...
    return response

Як і в Рівні 1, ви можете використовувати Query() для додавання валідації (min_length, max_length, gt, le, regex) та метаданих для документації.

POST-запити та валідація з Pydantic

POST-запити використовуються для надсилання даних від клієнта на сервер з метою створення нового ресурсу. Дані передаються в тілі запиту (request body), зазвичай у форматі JSON.

FastAPI використовує бібліотеку Pydantic для визначення структури, валідації та парсингу даних з тіла запиту.

Процес:

  1. Визначте Pydantic-модель, що описує очікувану структуру даних.
  2. Вкажіть цю модель як анотацію типу для аргумента функції ендпоінта.
  3. FastAPI автоматично:
    • Прочитає тіло запиту.
    • Перетворить JSON на об'єкт вашої Pydantic-моделі.
    • Провалідує дані. Якщо вони не відповідають моделі (неправильний тип, відсутні обов'язкові поля), поверне помилку 422.
    • Передасть валідний об'єкт моделі до вашої функції.

Приклад:

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

# 1. Pydantic-модель для валідації
class Item(BaseModel):
    name: str = Field(min_length=3, max_length=50)
    price: float = Field(gt=0, description="Ціна має бути більшою за нуль")
    is_offer: bool = False

# 2. Ендпоінт з анотацією типу
@app.post("/items/")
async def create_item(item: Item): # FastAPI валідує тіло запиту за моделлю Item
    # item — це екземпляр Pydantic-моделі Item
    print(f"Створено товар: {item.name}, ціна: {item.price}")
    return {"message": "Товар успішно створено!", "item_data": item.dict()}

PUT-запити: оновлення даних

PUT-запити використовуються для повного оновлення існуючого ресурсу. Клієнт повинен передати всі поля ресурсу, навіть ті, що не змінюються.

Логіка дуже схожа на POST: ми використовуємо Path Parameter для ідентифікації ресурсу і Pydantic-модель для валідації даних у тілі запиту.

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI()
# Імітація бази даних
items_db = {1: {"name": "Яблуко", "price": 10.5}}

class ItemUpdate(BaseModel):
    name: str
    price: float

@app.put("/items/{item_id}")
async def update_item(item_id: int, item_update: ItemUpdate):
    if item_id not in items_db:
        raise HTTPException(status_code=404, detail="Товар не знайдено")

    # Оновлюємо дані в нашій "базі"
    items_db[item_id] = item_update.dict()
    return {"message": "Товар успішно оновлено", "item": items_db[item_id]}
Примітка

Для часткового оновлення (коли клієнт передає лише змінені поля) зазвичай використовується метод PATCH.

DELETE-запити

DELETE-запити використовуються для видалення ресурсу за його ідентифікатором. Зазвичай вони не мають тіла запиту.

from fastapi import FastAPI, HTTPException

app = FastAPI()
# Імітація бази даних
items_db = {
    1: {"name": "Яблуко", "price": 10.5},
    2: {"name": "Банан", "price": 15.0},
}

@app.delete("/items/{item_id}")
async def delete_item(item_id: int):
    if item_id not in items_db:
        # Використовуємо HTTPException для повернення коректної помилки
        raise HTTPException(status_code=404, detail="Товар не знайдено")

    deleted_item = items_db.pop(item_id)
    return {"message": f"Товар '{deleted_item['name']}' успішно видалено"}

Після успішного видалення часто повертають статус-код 204 No Content (без тіла відповіді) або 200 OK з повідомленням.

Обробка помилок та винятків

Для повернення HTTP-помилок з ендпоінтів слід використовувати HTTPException.

Імпорт: from fastapi import HTTPException

Використання: raise HTTPException(status_code=..., detail=...)

  • status_code: код стану HTTP (наприклад, 404, 400, 403).
  • detail: повідомлення про помилку, яке надішлеться клієнту в JSON-відповіді.
  • headers: опціональний словник з додатковими заголовками.

FastAPI перехопить цей виняток і сформує коректну HTTP-відповідь із зазначеним кодом і тілом.

Приклад:

from fastapi import FastAPI, HTTPException

users_db = {1: "Alice", 2: "Bob"}

@app.get("/users/{user_id}")
async def get_user_by_id(user_id: int):
    if user_id not in users_db:
        raise HTTPException(status_code=404, detail=f"Користувача з ID {user_id} не знайдено")

    if user_id == 1: # Приклад перевірки прав
        raise HTTPException(status_code=403, detail="Доступ до цього користувача заборонено")

    return {"username": users_db[user_id]}

Використання HTTPException — стандартний і правильний спосіб обробки очікуваних помилок в API.

CRUD API: повний приклад

Об'єднаємо всі операції для простого ресурсу "Книга".

Модель Pydantic:

from pydantic import BaseModel

class Book(BaseModel):
    id: int
    title: str
    author: str

Ендпоінти:

from fastapi import FastAPI, HTTPException
from typing import List

app = FastAPI()
books_db = [] # Імітація БД

# CREATE
@app.post("/books/", response_model=Book, status_code=201)
async def create_book(book: Book):
    books_db.append(book)
    return book

# READ (List)
@app.get("/books/", response_model=List[Book])
async def get_books():
    return books_db

# READ (Detail)
@app.get("/books/{book_id}", response_model=Book)
async def get_book(book_id: int):
    for book in books_db:
        if book.id == book_id:
            return book
    raise HTTPException(status_code=404, detail="Книгу не знайдено")

# UPDATE
@app.put("/books/{book_id}", response_model=Book)
async def update_book(book_id: int, book_update: Book):
    # ... (логіка пошуку та оновлення) ...
    return book_update

# DELETE
@app.delete("/books/{book_id}")
async def delete_book(book_id: int):
    # ... (логіка пошуку та видалення) ...
    return {"message": "Книгу видалено"}
