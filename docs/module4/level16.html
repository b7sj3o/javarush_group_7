Рівень 16: Інтеграція FastAPI із зовнішніми API

Розширення функціоналу вашого застосунку за рахунок інтеграції із зовнішніми сервісами — це ключова навичка сучасного розробника, яка дозволяє уникнути 'винаходу велосипеда'. Ми навчимося ефективно інтегрувати FastAPI із зовнішніми API, що значно прискорить розробку та дозволить використовувати готові, масштабовані рішення.

Ви дізнаєтеся, як працюють зовнішні API та навіщо потрібні API-ключі та принципи авторизації. Ключовим інструментом стане бібліотека httpx — сучасний асинхронний HTTP-клієнт, який дозволяє вашому FastAPI-застосунку залишатися неблокуючим під час очікування відповідей від сторонніх сервісів.

Особливу увагу приділимо валідації даних від зовнішніх API за допомогою Pydantic та надійній обробці мережевих та HTTP-помилок, а також коротко розглянемо специфіку взаємодії з GraphQL API.

Що таке зовнішні API і навіщо вони потрібні?

Зовнішній API — це інтерфейс, що надається стороннім сервісом, який дозволяє вашому застосунку програмно взаємодіяти з ним: отримувати дані або виконувати дії.

Замість того, щоб створювати з нуля складну функціональність, ви можете інтегрувати готове рішення.

Навіщо використовувати зовнішні API:

  • розширення функціональності: прийом платежів (Stripe), надсилання SMS (Twilio), робота з картами (Google Maps).
  • доступ до даних: отримання інформації про авіарейси, курси валют, наукові статті.
  • економія часу та ресурсів: ви використовуєте готову, підтримувану та масштабовану інфраструктуру іншого сервісу.

Інтеграція із зовнішніми API — це ключова навичка, що дозволяє створювати більш потужні та функціональні застосунки.

Як працює інтеграція із зовнішнім API

Процес взаємодії з більшістю REST API зводиться до чотирьох основних кроків.

Потік взаємодії

  1. Реєстрація та отримання API-ключа: майже всі сервіси вимагають реєстрації та отримання унікального ключа (API Key) або токена для ідентифікації вашого застосунку.
  2. Надсилання HTTP-запиту: ваш застосунок надсилає запит на потрібний URL (ендпоінт) зовнішнього API,водночас передає API-ключ та інші параметри.
  3. Отримання відповіді: зовнішній сервіс зазвичай повертає відповідь у форматі JSON.
  4. Обробка відповіді: ваш застосунок парсить JSON, валідує отримані дані та використовує їх у своїй логіці.

Бібліотека httpx

Для взаємодії із зовнішніми API в асинхронних застосунках, як-от FastAPI, стандартна бібліотека requests не підходить, оскільки вона є такою, що блокує.

httpx — це сучасна, швидка та потужна бібліотека для надсилання HTTP-запитів, яка підтримує як синхронний, так і асинхронний режими.

Встановлення:

pip install httpx
pip freeze > requirements.txt

Приклад асинхронного запиту:

import httpx
import asyncio

async def fetch_posts():
    # Використовуємо 'async with' для керування життєвим циклом клієнта
    async with httpx.AsyncClient() as client:
        # 'await' призупиняє виконання, поки ми чекаємо на відповідь від мережі
        response = await client.get("https://jsonplaceholder.typicode.com/posts/1")
        # Перевірити, чи був запит успішним (статус 2xx)
        response.raise_for_status()
        return response.json()

# Для запуску: asyncio.run(fetch_posts())

httpx є стандартом для виконання HTTP-запитів в асинхронному Python-коді.

Асинхронні GET та POST запити у FastAPI

Інтеграція httpx в ендпоінти FastAPI дозволяє вашому застосунку залишатися неблокуючим та обробляти інші запити, поки він чекає на відповідь від зовнішнього API.

Приклад GET-запиту:

from fastapi import FastAPI, HTTPException
import httpx

app = FastAPI()

@app.get("/external-users/{user_id}")
async def get_external_user(user_id: int):
    url = f"https://jsonplaceholder.typicode.com/users/{user_id}"
    async with httpx.AsyncClient() as client:
        response = await client.get(url)
        # Перевіряємо, що зовнішній сервіс відповів успішно
        if response.status_code != 200:
            raise HTTPException(status_code=response.status_code, detail="Помилка зовнішнього API")
        return response.json()

Приклад POST-запиту:

@app.post("/create-external-post/")
async def create_external_post(title: str, body: str):
    url = "https://jsonplaceholder.typicode.com/posts"
    payload = {"title": title, "body": body, "userId": 1}
    async with httpx.AsyncClient() as client:
        # Надсилаємо дані у форматі JSON
        response = await client.post(url, json=payload)
    return {"status_code": response.status_code, "response_data": response.json()}

Валідація даних від зовнішніх API за допомогою Pydantic

Ніколи не довіряйте даним, що надходять від зовнішніх API. Структура відповіді може змінитися, сервіс може повернути помилку або неочікувані дані. Використовуйте Pydantic-моделі для валідації відповідей.

Процес:

  1. Вивчіть документацію зовнішнього API та створіть Pydantic-модель, що описує очікувану структуру відповіді.
  2. Після отримання відповіді від API та її перетворення на JSON, пропустіть ці дані через вашу Pydantic-модель.
  3. Якщо валідація проходить успішно, ви можете бути впевнені у структурі та типах даних.
  4. Якщо валідація не проходить, обробіть помилку, залогуйте її та поверніть клієнту коректну відповідь.

Приклад (API погоди):

from pydantic import BaseModel, Field, ValidationError

Обробка помилок при роботі із зовнішніми сервісами

При роботі з мережею завжди щось може піти не так. Ваш код має бути до цього готовим.

Мережеві помилки:

  • httpx.ConnectError: не вдалося встановити з'єднання (сервіс недоступний, невірна адреса).
  • httpx.TimeoutException: сервіс не відповів за вказаний час.

HTTP-помилки:

  • httpx.HTTPStatusError: сервіс відповів з кодом 4xx (помилка клієнта) або 5xx (помилка сервера). Генерується методом response.raise_for_status().

Патерн обробки помилок:

import httpx
from fastapi import HTTPException

async def fetch_data_safely(url: str):
    try:
        async with httpx.AsyncClient(timeout=10.0) as client:
            response = await client.get(url)
            # Перевіряємо, що статус відповіді 2xx. Якщо ні — згенерує HTTPStatusError.
            response.raise_for_status()
            return response.json()
    except httpx.TimeoutException:
        # Помилка таймауту
        raise HTTPException(status_code=504, detail="Зовнішній сервіс не відповів вчасно.")
    except httpx.ConnectError:
        # Помилка з'єднання
        raise HTTPException(status_code=503, detail="Не вдалося підключитися до зовнішнього сервісу.")
    except httpx.HTTPStatusError as e:
        # Помилка зі статусом 4xx або 5xx
        raise HTTPException(
            status_code=e.response.status_code,
            detail=f"Зовнішній сервіс повернув помилку: {e.response.text}"
        )

Використання try...except та response.raise_for_status() є обов'язковим для створення надійних інтеграцій.

Інтеграція з GraphQL API

Взаємодія із зовнішнім GraphQL API з FastAPI також здійснюється через httpx, але структура запиту відрізняється.

Процес:

  1. Завжди використовується метод POST.
  2. URL завжди один і той самий (ендпоінт GraphQL).
  3. Тіло POST-запиту — це JSON, що містить:
    • query: рядок з вашим GraphQL-запитом.
    • variables (опціонально): словник зі змінними для запиту.

Приклад запиту до публічного API країн:

import httpx
from fastapi import FastAPI

app = FastAPI()

@app.get("/countries/{code}")
async def get_country_info(code: str):
    graphql_endpoint = "https://countries.trevorblades.com/"
    # 1. Формуємо GraphQL-запит
    query = """
        query GetCountry($code: ID!) {
          country(code: $code) {
            name
            capital
            currency
            languages {
              name
            }
          }
        }
    """
    # 2. Формуємо змінні
    variables = {"code": code.upper()}

    async with httpx.AsyncClient() as client:
        # 3. Надсилаємо POST-запит
        response = await client.post(
            graphql_endpoint,
            json={"query": query, "variables": variables},
        )
    response.raise_for_status()
    # 4. Обробляємо відповідь
    return response.json()["data"]["country"]

Дані, отримані від GraphQL API, також слід валідувати за допомогою Pydantic.
