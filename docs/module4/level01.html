Рівень 1: Вступ до FastAPI

Створення швидких, сучасних та надійних API часто пов'язане з купою технічних викликів. FastAPI — це потужний Python-фреймворк, який вирішує ці завдання, пропонуючи високопродуктивну асинхронну архітектуру.

Ми розберемо його ключові фішки та переваги, які відрізняють його від Django, освоїмо базову інсталяцію та запуск аплікації. Ви навчитеся створювати GET-ендпоінти, ефективно працювати з динамічними параметрами шляху та запиту, а також формувати коректні JSON-відповіді.

Особливу увагу приділимо вбудованій автоматичній генерації інтерактивної документації OpenAPI (Swagger UI), яка кардинально спрощує розробку та тестування API. По завершенні ви зможете впевнено створювати функціональні та добре документовані REST API.

Що таке FastAPI і чому він важливий

FastAPI — це сучасний, високопродуктивний вебфреймворк на Python для створення API та мікросервісів.

Його розроблено на основі асинхронної архітектури ASGI (Asynchronous Server Gateway Interface), що дозволяє йому ефективно обробляти велику кількість одночасних з'єднань. Завдяки цьому він є ідеальним вибором для високонавантажених систем, real-time застосунків (чати, сповіщення) та мікросервісної архітектури.

Ключові особливості:

  • один із найшвидших фреймворків на Python, що конкурує з NodeJS та Go.
  • вбудована підтримка async та await для неблокуючих операцій.
  • використовує стандартні анотації типів Python та бібліотеку Pydantic для валідації даних, що зменшує кількість помилок.
  • автоматично генерує інтерактивну документацію API (Swagger UI / OpenAPI та ReDoc) безпосередньо з вашого коду.
  • мінімалістичний синтаксис та автодокументація значно прискорюють процес створення API.

Базова архітектура FastAPI

Щоб розуміти, чому FastAPI такий ефективний, важливо бачити його архітектуру в цілому. Процес обробки одного запиту можна уявити як конвеєр, де кожен компонент виконує своє чітке завдання.

Порівняння FastAPI з Django та Flask

Критерій Django Flask FastAPI
Тип монолітний фреймворк («батарейки в комплекті») мікрофреймворк (мінімалістичний) мікрофреймворк (орієнтований на API)
Основне застосування великі вебзастосунки, сайти з адмін-панеллю прості сайти, прототипи, гнучкі проєкти високопродуктивні API, мікросервіси
Асинхронність (ASGI) підтримується, але не є основною парадигмою потребує додаткового налаштування (Flask 2.0+) вбудована в ядро, ключова перевага
Валідація даних Django Forms / DRF Serializers потребує сторонніх бібліотек (Marshmallow, WTForms) вбудована через Pydantic (строга типізація)
Документація API потребує DRF або сторонніх бібліотек потребує сторонніх бібліотек (Flasgger) автоматична (Swagger UI, ReDoc) «з коробки»

Django є чудовим вибором для монолітних сайтів. Flask дає максимальну гнучкість. FastAPI — найкращий вибір для створення сучасних, швидких і надійних API, завдяки вбудованій асинхронності, валідації даних та автодокументації.

Встановлення FastAPI та Uvicorn

FastAPI — це сам фреймворк. Для його запуску необхідний ASGI-сервер, який оброблятиме асинхронні запити. Найпопулярніший сервер для FastAPI — це Uvicorn.

Кроки встановлення (рекомендовано у віртуальному оточенні):

  1. Створення та активація віртуального оточення: 
    python -m venv venv
source venv/bin/activate  # macOS/Linux
# venv\Scripts\activate    # Windows
  2. Встановлення FastAPI: 
    pip install fastapi
  3. Встановлення Uvicorn:

    Пакет "uvicorn[standard]" містить додаткові залежності для кращої продуктивності.

    pip install "uvicorn[standard]"
  4. Збереження залежностей: 
    pip freeze > requirements.txt

Налаштування проєкту та структура застосунку FastAPI

Для FastAPI не існує сталої, обов'язкової структури проєкту, як у Django. Однак для підтримки порядку рекомендується дотримуватися певних домовленостей.

Мінімальна структура:

my_project/
└── main.py

У файлі main.py створюється екземпляр FastAPI і визначаються ендпоінти.

Рекомендована структура для середніх та великих проєктів:

my_project/
├── app/                  # Основна папка застосунку
│   ├── __init__.py
│   ├── main.py           # Головний файл, що збирає застосунок
│   ├── core/
│   │   └── config.py     # Налаштування
│   ├── routers/
│   │   ├── __init__.py
│   │   └── posts.py      # Маршрути для постів
│   │   └── users.py      # Маршрути для користувачів
│   ├── schemas/
│   │   └── posts.py      # Pydantic моделі (схеми)
│   └── crud/
│       └── posts.py      # Функції для роботи з БД
├── tests/                # Папка з тестами
└── .env                  # Змінні оточення

У main.py роутери з папки routers/ підключаються до основного застосунку за допомогою app.include_router(). Це робить код модульним і легким для читання.

Створення першого простого API (GET-запит)

У FastAPI ендпоінти створюються за допомогою декораторів операцій шляху (Path Operation Decorators).

Для обробки GET-запиту використовується декоратор @app.get().

Приклад (main.py):

from fastapi import FastAPI

# 1. Створюємо екземпляр застосунку FastAPI
app = FastAPI()

# 2. Визначаємо ендпоінт для GET-запиту за кореневим URL ("/")
# Ця функція викликатиметься, коли хтось зайде на http://127.0.0.1:8000/
@app.get("/")
def read_root():
    # 3. Повертаємо словник, який FastAPI автоматично перетворить у JSON
    return {"message": "Hello, World!"}

# Інший ендпоінт
@app.get("/items/")
def get_items():
    return {"items": ["Яблуко", "Банан", "Апельсин"]}

Запуск сервера. У терміналі, перебуваючи в папці з main.py, виконайте:

uvicorn main:app --reload
  • main: ім'я файлу main.py.
  • app: ім'я змінної з екземпляром FastAPI у файлі.
  • --reload: сервер автоматично перезапускатиметься при змінах у коді.

Концепція ендпоінтів

Маршрутизація (Routing) у FastAPI — це процес зіставлення URL-адреси та HTTP-методу запиту з конкретною функцією-обробником (ендпоінтом).

Path Operations

FastAPI надає декоратори для всіх основних HTTP-методів:

  • @app.get()
  • @app.post()
  • @app.put()
  • @app.delete()
  • @app.patch(), @app.options(), @app.head(), @app.trace()

Path Parameters
Ви можете визначати динамічні частини в URL, використовуючи фігурні дужки. Значення цих частин передаватимуться у вашу функцію як аргументи. FastAPI автоматично валідує їх тип на основі анотацій типів Python.

@app.get("/items/{item_id}")
def read_item(item_id: int): # FastAPI перевірить, що item_id — це число
    return {"item_id": item_id, "description": f"Це товар номер {item_id}"}

Запит: GET /items/123 -> item_id буде 123 (тип int).
Запит: GET /items/abc -> FastAPI поверне помилку 422 Unprocessable Entity.

Query Parameters

Query Parameters — це параметри, що передаються до URL після знака ? у вигляді пар ключ=значення. Вони використовуються для фільтрації, сортування або пагінації.

Приклад URL: /items/?skip=0&limit=10

У FastAPI Query Parameters визначаються як аргументи функції, які не є частиною шляху.

Приклад:

from fastapi import FastAPI, Query
from typing import Optional, List # Для опціональних параметрів та списків

app = FastAPI()

# Базовий приклад з опціональним параметром
@app.get("/search")
def search_items(query: Optional[str] = None): # 'query' - це Query Parameter
    if query:
        return {"message": f"Пошук за запитом: '{query}'"}
    return {"message": "Показати всі елементи"}

# Приклад з валідацією та значеннями за замовчуванням
@app.get("/products")
def get_products(
    is_available: bool = True, # Обов'язковий (бо немає Optional), за замовчуванням True
    limit: int = Query(10, gt=0, le=100), # Валідація: limit > 0 і <= 100
    tags: Optional[List[str]] = Query(None) # Список query-параметрів
):
    # URL: /products/?tags=new&tags=sale
    # tags буде ['new', 'sale']
    return {"limit": limit, "is_available": is_available, "tags": tags}

Використання Query() з fastapi дозволяє додавати валідацію (більше, менше, довжина рядка тощо) та метадані для документації.

Відповіді від API: формати даних

FastAPI за замовчуванням повертає відповіді у форматі JSON. Ви можете повертати з функції-обробника стандартні типи Python, і FastAPI автоматично їх перетворить:

  • dict -> JSON object {}
  • list -> JSON array []
  • str, int, float, bool -> JSON string, number, boolean

Використання response_model
Для забезпечення строгої типізації відповіді API, можна використовувати аргумент декоратора response_model. Він приймає Pydantic-модель і гарантує, що відповідь буде узгодженою з її структурою (відфільтрує зайві поля, перетворить типи).

from fastapi import FastAPI
from pydantic import BaseModel
from typing import Optional

class UserOut(BaseModel): # Pydantic модель для відповіді
    id: int
    username: str
    email: Optional[str] = None

app = FastAPI()

@app.get("/users/{user_id}", response_model=UserOut)
def get_user(user_id: int):
    # Припустимо, ми отримали з БД об'єкт із зайвими полями (наприклад, хеш пароля)
    user_from_db = {
        "id": user_id,
        "username": "alex",
        "email": "alex@example.com",
        "hashed_password": "very_secret_hash_value"
    }
    # FastAPI відфільтрує відповідь згідно з UserOut, і hashed_password не потрапить у JSON
    return user_from_db

Це також покращує автоматичну документацію, показуючи точну схему відповіді.

Вбудована документація з OpenAPI (Swagger)

Однією з головних переваг FastAPI є автоматична генерація інтерактивної документації API.

Як це працює:

  • FastAPI аналізує ваш код: шляхи, декоратори операцій (@app.get), параметри функцій, їхні анотації типів, Pydantic-моделі.
  • На основі цього аналізу він генерує схему API відповідно до стандарту OpenAPI.
  • Ця схема використовується для створення двох варіантів інтерактивної документації, доступних у браузері.

URL документації (за замовчуванням):

  • /docs: інтерактивний інтерфейс Swagger UI. Дозволяє не тільки переглядати документацію, але й тестувати ендпоінти прямо з браузера.
  • /redoc: альтернативний інтерфейс ReDoc. Надає чисту та зрозумілу документацію (без можливості надсилання запитів).

Приклад мінімального застосунку FastAPI

Цей приклад поєднує кілька розглянутих концепцій.

Файл main.py:

from fastapi import FastAPI, Query
from pydantic import BaseModel
from typing import Optional, List

# --- Pydantic модель для відповіді ---
class Item(BaseModel):
    id: int
    name: str
    is_offer: Optional[bool] = None

# --- Екземпляр FastAPI ---
app = FastAPI(
    title="Мій Перший API",
    description="Це демонстраційний API на FastAPI",
    version="1.0.0",
)

# --- Дані (імітація БД) ---
db_items = {
    1: {"id": 1, "name": "Яблуко"},
    2: {"id": 2, "name": "Банан", "is_offer": True},
    3: {"id": 3, "name": "Апельсин"},
}

# --- Ендпоінти ---
@app.get("/", summary="Кореневий ендпоінт")
async def read_root():
    return {"message": "Ласкаво просимо до FastAPI!"}

@app.get("/items/", response_model=List[Item], summary="Отримати список товарів")
async def get_items(limit: int = Query(10, gt=0, le=100)):
    return list(db_items.values())[:limit]

@app.get("/items/{item_id}", response_model=Item, summary="Отримати товар за ID")
async def get_item_by_id(item_id: int):
    return db_items.get(item_id)

Запуск: uvicorn main:app --reload.
Тестування: відкрийте http://127.0.0.1:8000/docs у браузері.
