# План реалізації — 5 занять × ~2 год

## Поточний стан проекту

### Вже готово (не чіпаємо):
- `frontend/` — повністю готовий
- `nginx.conf`, `docker-compose.yml`, `backend/Dockerfile` — готові
- `db/1-init.sql` — CREATE TABLE готовий

### Треба реалізувати:
- `backend/config.py` — порожній
- `backend/db.py` — порожній
- `backend/handlers.py` — порожній
- `backend/utils/validators.py` — порожній
- `backend/app.py` — маршрутизація є, але хендлери — заглушки (`...`)
- `backend/requirements.txt` — відсутній `psycopg2-binary`

## Заняття 1 — Docker + Розуміння проекту

### Теорія (30 хв)
- Що таке Docker, контейнери, образи
- Як `docker-compose.yml` описує кілька сервісів
- Docker-мережі: як `backend`, `nginx`, `postgres` знаходять одне одного за іменем сервісу

### Практика (90 хв)
- Пройтись по всіх існуючих файлах: `nginx.conf`, `docker-compose.yml`, `Dockerfile`, `app.py`
- Запустити `docker compose up --build` — побачити що стартує, а що падає
- Відкрити в браузері `http://localhost:8080` — переконатись що фронтенд відображається
- Перевірити nginx-проксі: `curl http://localhost:8080/api/upload/` — має дійти до backend
- Розібрати логи кожного контейнера: `docker compose logs`

**Результат:** Всі 3 контейнери запущені, фронтенд відображається, nginx правильно проксіює запити до backend

## Заняття 2 — Python backend: конфігурація + валідація

### Теорія (20 хв)
- Як працює `BaseHTTPRequestHandler` (`do_GET`, `do_POST`, `do_DELETE`)
- Що таке HTTP-заголовки, тіло запиту, статус-коди
- Як Python читає змінні середовища (`os.environ`, `python-dotenv`)

### Практика (100 хв)
- Реалізувати `backend/config.py`: константи (`ALLOWED_TYPES`, `MAX_SIZE`, `IMAGES_DIR`, `LOGS_DIR`)
- Реалізувати `backend/utils/validators.py`: `validate_extension()`, `validate_size()`
- Покращити маршрутизацію в `backend/app.py`: правильні 404, `do_DELETE`
- Зробити `handle_images()` повноцінним (поки що — заглушка зі списком з файлової системи, без БД)
- Протестувати через `curl` або Postman

**Результат:** Backend відповідає на запити, валідатори працюють, правильні HTTP-статуси

## Заняття 3 — Завантаження файлів + Логування

### Теорія (20 хв)
- Що таке `multipart/form-data` — як файли передаються через HTTP
- Python `cgi` або ручний парсинг multipart
- Модуль `logging`: формати, рівні (`INFO`, `ERROR`), FileHandler

### Практика (100 хв)
- Реалізувати `backend/handlers.py`: `handle_upload()` — читає файл з тіла запиту, валідує, генерує UUID-ім'я, зберігає в `/images`
- Додати логування (`app.log` у `/logs`) — успішне завантаження і помилки
- Перевірити через фронтенд: завантажити картинку → вона зберігається у volume
- Перевірити лог-файл: `docker exec <container> cat /logs/app.log`

**Результат:** Файли завантажуються і зберігаються, кожна подія логується

## Заняття 4 — PostgreSQL: зберігання метаданих + всі ендпоінти

### Теорія (20 хв)
- Як Python підключається до PostgreSQL через `psycopg2`
- Параметризовані запити (чому `%s`, а не f-рядки — захист від SQL-ін'єкцій)
- Пагінація через `LIMIT` / `OFFSET`

### Практика (100 хв)
- Додати `psycopg2-binary` до `requirements.txt`
- Реалізувати `backend/db.py`: `save_image()`, `get_images()` з пагінацією, `delete_image()`
- Оновити `handle_upload()`: після збереження файлу — записати метадані в БД
- Реалізувати `handle_images()`: читає з БД, повертає JSON з пагінацією
- Реалізувати `handle_delete()`: видаляє з БД + файл з `/images`
- Протестувати повний цикл через фронтенд

**Результат:** Повний CRUD — завантажити, побачити список, видалити. Дані в PostgreSQL

## Заняття 5 — Тестування + Резервні копії + Фінальний огляд

### Теорія (20 хв)
- Persistency у Docker: що відбувається після `docker compose down`
- `pg_dump` і `psql` для backup/restore

### Практика (100 хв)
- Тест на персистентність: зупинити контейнери, запустити знову — перевірити що дані збереглись
- Виконати команду резервної копії:
  ```bash
  docker exec -t postgres pg_dump -U $DB_USER $DB_NAME > backups/backup_$(date +%F_%H%M%S).sql
  ```
- Перевірити edge-кейси: завантажити неправильний формат, файл >5 МБ
- Фінальне ревʼю коду: чистота, назви функцій, коментарі
- Запустити повне демо від А до Я

**Результат:** Готовий, протестований проект з повним backup/restore
